### UE_06.0_1: Referenzen vs. Primitive

Analysiere folgenden Code:

```java
public class ReferenceTest {
    public static void main(String[] args) {
        int a = 10;
        int b = a;
        b = 20;
        System.out.println("a = " + a + ", b = " + b);

        Patient p1 = new Patient("Anna", 25);
        Patient p2 = p1;
        p2.setName("Ben");
        System.out.println("p1: " + p1.getName() + ", p2: " + p2.getName());
    }
}
```

1. Was wird ausgegeben? Begründe die unterschiedlichen Ergebnisse.
2. Erstelle ein Diagramm, das die Speichersituation zeigt (primitiv vs. Referenz)

### UE_06.0_2: Methodenparameter

```java
public class ParameterTest {
    public static void changeAge(Patient p) {
        p.setAge(50);
    }

    public static void changeNumber(int x) {
        x = 100;
    }

    public static void main(String[] args) {
        Patient p = new Patient("Anna", 25);
        changeAge(p);
        System.out.println(p.getAge());  // ?

        int number = 25;
        changeNumber(number);
        System.out.println(number);          // ?
    }
}
```

1. Was wird ausgegeben? Begründe.
2. Was bedeutet "Call by Value" in Java? Warum verhält sich der Patient anders als der int?

### UE_06.0_4: Immutable Finding class

Erstelle eine immutable Klasse `Finding`:

- `final`-Klasse
- Alle Attribute sind `private final`:
  - `patientId` (String)
  - `diagnosis` (String)
  - `measuredValue` (double)
  - `date` (String)
- Einziger Konstruktor (setzt alle Werte)
- Nur Getter (keine Setter)
- Eine Methode `display()`, die alle Werte ausgibt

Erstelle in der `main`-Methode einen Befund und weise ihn einer zweiten Variable zu. Zeige, dass eine Änderung nicht möglich ist.

### UE_06.0_5 Stammbaum

Erstelle eine Klasse `Person`, welche für einen Stammbaum verwendet wird,
so dass sie dem folgenden UML-Klassendiagramm entspricht:

![stammbaum](../img/06_0_stammbaum.svg)

**Attribute:**
- `name` Name der Person (`String`)
- `gender` kann den Wert `w` oder `m` enthalten (`char`)
- `birth` das Geburtsdatum (`LocalDate`, wird mit `null` initialisiert)
- `mother` Referenz auf die Mutter der Person, wird mit `null` initialisiert
- `father` Referenz auf den Vater der Person, wird mit `null` initialisiert
- `children` Referenz auf die Kinder der Person, wird mit einer leeren Liste initialisiert

**Methoden:**
- Konstruktor
  bekommt als Argumente den Namen und das Geschlecht übergeben
- `addChild(child)`
  Fügt eine andere Person-Instanz als Kind ein.
  Gleichzeitig wird die Person, bei welcher das Kind eingefügt wird,
  dem Kind als Mutter oder Vater gesetzt (je nach Geschlecht)
- `ancestors()` gibt eine Liste aller Nachkommen der Person
  (Kinder, Enkelkinder, Urenkel, ...) zurück
- `descendants()` gibt eine Liste aller Vorfahren der Person
  (Eltern, Großeltern, ...) zurück
- `siblings()` gibt eine Liste aller Geschwister der Person zurück

Erstelle dann eine Klasse mit einer `main`-Methode, 
in welcher mithilfe deiner 
Klasse `Person` dein eigener Stammbaum zusammengestellt wird.
Es sollten Personen von mindestens 3 Generationen vorkommen.
(Falls du nicht deine eigenen Daten verwenden willst,
kannst du auch einen fiktiven Stammbaum zusammensetzen.)

Du kannst z.B. auch einen Teil des Stammbaums der Habsburger nachbilden:
https://habsburg.org/familiengeschichte-stammbaum/grosser-stammbaum/

Rufe dann die Methoden `descendants`, `ancestors` und `siblings`
von einigen Personen in deinem Stammbaum
auf und gib die Namen der Personen aus,
welche in der jeweiligen Listen enthalten sind.
Überprüfe das Ergebnis.
