### UE_11.2_1: Datenbanktabellen anlegen

Erstelle mit einem MySQL-Client folgende Tabellen:

```sql
CREATE TABLE patient (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);

CREATE TABLE address (
    id INT AUTO_INCREMENT PRIMARY KEY,
    street VARCHAR(100),
    city VARCHAR(100),
    patient_id INT UNIQUE,
    FOREIGN KEY (patient_id) REFERENCES patient(id)
);

CREATE TABLE finding (
    id INT AUTO_INCREMENT PRIMARY KEY,
    diagnosis VARCHAR(200),
    patient_id INT,
    FOREIGN KEY (patient_id) REFERENCES patient(id)
);
```

### UE_11.2_2: Entity-Klassen mit @ManyToOne

Erstelle eine Entity `Finding` mit:
- `id` (int, `@Id`, `@GeneratedValue`)
- `diagnosis` (String)
- `patient` (`@ManyToOne(fetch = FetchType.LAZY)`, `@JoinColumn(name = "patient_id")`)

Ergänze `Patient` um:
- `findings` (`@OneToMany(mappedBy = "patient", cascade = CascadeType.ALL, orphanRemoval = true)`)

### UE_11.2_3: Patienten mit Findings speichern

Schreibe ein Programm `PatientWithFinding.java`:

1. Erstelle einen Patienten mit 2–3 Findings
2. Setze die Beziehung auf beiden Seiten (`f.setPatient(p)` und `p.getFindings().add(f)`)
3. Speichere den Patienten mit `em.persist(p)` – die Findings sollten durch Cascade mitgespeichert werden
4. Gib die generierten IDs aus

### UE_11.2_4: Findings lazy laden

Schreibe ein Programm `LazyLoadTest.java`:

1. Rufe einen Patienten mit `em.find()` ab
2. Greife innerhalb der Transaktion auf `p.getFindings()` zu (z. B. `p.getFindings().size()`)
3. Greife nach dem `commit()` auf `p.getFindings()` zu – beobachte die `LazyInitializationException`
4. Kommentiere den Zugriff nach dem commit aus

### UE_11.2_5: JOIN FETCH in JPQL

Schreibe ein Programm `JoinFetchTest.java`:

1. Führe eine JPQL-Abfrage mit `JOIN FETCH` aus:
   ```java
   TypedQuery<Patient> query = em.createQuery(
       "SELECT p FROM Patient p JOIN FETCH p.findings WHERE p.id = :id", Patient.class);
   ```
2. Greife nach dem `commit()` auf `p.getFindings()` zu – es sollte funktionieren
3. Gib alle Findings des Patienten aus

### UE_11.2_6: @OneToOne – Address

Erstelle eine Entity `Address` mit `@OneToOne` zu `Patient`:

1. `Address` hat `id`, `street`, `city` und `patient` (`@OneToOne`, `@JoinColumn(name = "patient_id")`)
2. Ergänze `Patient` um `address` (`@OneToOne(mappedBy = "patient", cascade = CascadeType.ALL)`)
3. Speichere einen Patienten mit Adresse
4. Rufe den Patienten ab und gib Adresse aus

### UE_11.2_7: CascadeTypes vergleichen

Schreibe ein Programm `CascadeTest.java`:

1. Erstelle einen Patienten mit 2 Findings und speichere ihn
2. Lösche den Patienten mit `em.remove()` – durch `CascadeType.ALL` sollten auch die Findings gelöscht werden
3. Ändere `CascadeType.ALL` auf `CascadeType.PERSIST` – nun sollte das Löschen fehlschlagen
4. Erkläre in Kommentaren das Verhalten

### UE_11.2_8: Finding mit Verweis auf Patienten speichern

Schreibe ein Programm `FindingPersist.java`:

1. Rufe einen vorhandenen Patienten ab
2. Erstelle einen neuen Finding und setze den Patienten
3. Speichere den Finding mit `em.persist(finding)` (ohne Cascade)
4. Gib den Finding mit Patientennamen aus
