# UE_13.2 Spring Data JPA Repositories – Übungen

[<<](../skriptum/13.2_Spring_Data_JPA.md)

Diese Übungen setzen auf der **eigenen Übungs-Applikation** (z. B. "BookManager" aus UE_13.1) auf. Füge dafür den Starter `data-jpa` und einen MySQL-Treiber hinzu und konfiguriere die Datenbank in `application.properties`.

### UE_13.2_1: Entität und Repository anlegen

1. Erstelle eine `Book`-Entität: `@Entity`, Felder `id` (`@Id`, `@GeneratedValue`), `title`, `year`
2. Erstelle ein Interface `BookRepository extends JpaRepository<Book, Long>` (ohne eigene Methoden)
3. Schließe den Kreis: Injiziere `BookRepository` per Konstruktor-Injection in `BookController`

### UE_13.2_2: Standard-Methoden nutzen

Ergänze Beanspruchung der Standard-Methoden im Controller:

1. `findAll()` um alle Bücher anzuzeigen
2. `save(book)` in der POST-Methode aus UE_13.1
3. Skizziere zusätzlich, wie du `deleteById(id)` einsetzen würdest, und nenne den SQL-Code, den `findAll()` und `save()` erzeugen

### UE_13.2_3: Abgeleitete Query-Methoden

Schreibe eine **unabhängige** kleine App (Beispiel-Domain: `Student` mit `name` und `grade`). Erstelle passend:

1. `findByName(String name)`
2. `findByGradeGreaterThan(int grade)`
3. `findByNameContaining(String text)`
4. `findByGradeLessThanEqual(int maxGrade)`

Erkläre für jede Methode, welches SQL Spring Data daraus ableitet.

### UE_13.2_4: Optional & orElseThrow

1. Erkläre, warum `findById` ein `Optional<Book>` zurückgibt und welchen Vorteil das gegenüber `null` bietet.
2. Schreibe einen Controller-Aufruf mit `orElseThrow()` für eine Detailseite (aus UE_13.1_3) und prüfe, was passiert, wenn die id nicht existiert.
