# UE_11.0 Unit-Tests mit JUnit – Übungen

### UE_11.0_1: Maven-Projekt mit JUnit einrichten

Erstelle ein neues Maven-Projekt in IntelliJ:

1. New Project → Build-System: **Maven**, `groupId` = `com.example`, `artifactId` = `medical`
2. Öffne die erzeugte `pom.xml` und beschreibe in einem Kommentar die Bedeutung von `groupId`, `artifactId` und `version`
3. Füge die JUnit-Abhängigkeit mit `<scope>test</scope>` ein (Koordination: `org.junit.jupiter:junit-jupiter`)
4. Lade die Dependencies herunter (Reload All Maven Projects) und prüfe unter `~/.m2/repository\org\junit`, dass die Library dort ankommt
5. Erkläre kurz, warum der Scope `test` wichtig ist (vs. `compile`)

### UE_11.0_2: Erste Tests für Patient

Erstelle eine Klasse `Patient` mit `name`, `age` und `diagnosis` (inkl. Konstruktor, Getter und Setter). Lege `age` als `int` an.

Schreibe in `src/test/java` eine Testklasse `PatientTest`:

1. Teste mit `assertEquals`, dass `getName()` und `getDiagnosis()` die korrekten Werte zurückgeben
2. Teste mit `assertEquals`, dass `getAge()` das gesetzte Alter zurückgibt
3. Führe die Tests in IntelliJ aus und prüfe, dass alle grün sind

### UE_11.0_3: Assertions einsetzen

Ergänze `PatientTest` um Tests für folgende Assertions:

1. `assertNotNull` auf ein `Patient`-Objekt nach Konstruktor-Aufruf
2. `assertTrue` / `assertFalse`: füge eine Methode `boolean isAdult()` zu `Patient` hinzu (wahr ab Alter 18) und teste sie für zwei Alterswerte
3. `assertNotEquals`: prüfe `getAge()` gegen ein falsches Alter

### UE_11.0_4: Exceptions testen mit assertThrows

Erweitere `Patient` um eine `setAge(int age)`-Methode, die bei negativen Werten eine `IllegalArgumentException` wirft.

Schreibe einen Test, der mit `assertThrows(IllegalArgumentException.class, () -> p.setAge(-5))` prüft, dass:
1. negative Werte eine Exception werfen
2. der Aufruf `setAge(-5)` in der `assertThrows`-Methode als Lambda übergeben wird
3. ein gültiger Wert (z. B. `25`) **keine** Exception wirft (teste das durch einen normalen `assertEquals`-Aufruf danach)

### UE_11.0_5: @BeforeEach verwenden

Refaktoriere `PatientTest` so, dass das `Patient`-Objekt in einer `@BeforeEach`-Methode `setUp()` erzeugt und in einem Feld gespeichert wird. Entferne die doppelte Erzeugung aus den einzelnen Testmethoden.

Prüfe danach, dass alle Tests weiterhin bestehen und zeige, dass jeder Test mit einem **frischen** Objekt startet.

### UE_11.0_6: mvn test in der Kommandozeile

Führe in deinem Projektordner `mvn test` aus und prüfe die Ausgabe `Tests run: X, Failures: 0, Errors: 0, Skipped: 0`.

Führe dann `mvn dependency:tree` aus und gib die Liste der (auch transitiven) Abhängigkeiten wieder.

**Zusatzfrage:** Warum muss die `junit-jupiter`-Dependency mit `<scope>test</scope>` versehen werden – und was würde passieren, wenn du sie stattdessen mit dem Standard-Scope `compile` einfügst?
