### UE_12.1_1: Dependencies und persistence.xml einrichten

**Voraussetzung:** Die Maven-Grundlagen (Maven-Projekt erstellen, Dependencies eintragen) hast du bereits in [Kapitel 11.0](../skriptum/11.0_Unit_Test_JUnit.md) / UE_11.0_1 gelernt. Erstelle hier ein Maven-Projekt (`groupId` = `com.example`, `artifactId` = `medical-jpa`).

**Teil A – Dependencies hinzufügen:**

1. Füge in `pom.xml` innerhalb von `<dependencies>` die drei Abhängigkeiten ein:
   - `org.hibernate.orm:hibernate-core` (Hibernate/JPA-Implementierung)
   - `com.mysql:mysql-connector-j` (MySQL-Treiber)
   - `jakarta.persistence:jakarta.persistence-api` (JPA-Schnittstelle)
2. Lade die Dependencies herunter (Reload All Maven Projects) und prüfe unter `~/.m2/repository`, dass die `.jar`-Dateien dort gelandet sind
3. Starte in der Kommandozeile `mvn dependency:tree` und erkläre, welche (auch transitiven) Abhängigkeiten angezeigt werden

**Teil B – persistence.xml:**

4. Erstelle `src/main/resources/META-INF/persistence.xml` mit einer `persistence-unit` namens `medicalPU`
5. Konfiguriere die Verbindung zu einer MySQL-Datenbank `medical`
6. Setze `hibernate.hbm2ddl.auto` auf `update`
7. Baue das Projekt mit `mvn clean package` und prüfe, dass `target/medical-jpa-1.0-SNAPSHOT.jar` erzeugt wurde

**Zusatzfrage:** Warum musst du beim Maven-Projekt keine `.jar`-Dateien manuell herunterladen – im Gegensatz zum JDBC-Zugriff aus Kapitel 12.0? 

### UE_12.1_2: Entity-Klasse erstellen

Erstelle eine Entity-Klasse `Patient` im Package `com.example.medical.model` mit:

- `id` (int, `@Id`, `@GeneratedValue(strategy = IDENTITY)`)
- `name` (String, `@Column(nullable = false)`)
- `age` (int)
- `diagnosis` (String)
- Standard-Konstruktor, parametrisierten Konstruktor, Getter/Setter
- `toString()`

### UE_12.1_3: Patienten speichern (persist)

Schreibe ein Programm `PatientPersistieren.java`:

1. Erzeuge einen `EntityManager` über die persistence-unit `medicalPU`
2. Erstelle 3 `Patient`-Objekte
3. Speichere sie mit `em.persist()` in einer Transaktion
4. Gib nach dem Commit die generierten IDs aus
5. Schließe `EntityManager` und `EntityManagerFactory`

### UE_12.1_4: Patienten abrufen (find)

Schreibe ein Programm `PatientFinden.java`:

1. Frage den Benutzer nach einer ID (mit `Scanner`)
2. Rufe den Patienten mit `em.find(Patient.class, id)` ab
3. Gib die Patientendaten aus oder eine Meldung, falls nicht gefunden

### UE_12.1_5: JPQL-Abfragen

Schreibe ein Programm `PatientJpql.java` mit folgenden Abfragen:

1. Alle Patienten: `SELECT p FROM Patient p`
2. Patienten mit einer bestimmten Diagnose: `SELECT p FROM Patient p WHERE p.diagnosis = :diag`
3. Patienten über einem bestimmten Alter: `SELECT p FROM Patient p WHERE p.age > :min`
4. Anzahl der Patienten: `SELECT COUNT(p) FROM Patient p`

### UE_12.1_6: Patienten aktualisieren (merge)

Schreibe ein Programm `PatientAktualisieren.java`:

1. Rufe einen Patienten mit `em.find()` ab (managed)
2. Ändere seine Diagnose
3. Führe `commit()` aus – die Änderung sollte automatisch gespeichert werden
4. Rufe den Patienten erneut ab und gib die aktualisierten Daten aus

### UE_12.1_7: Patienten löschen (remove)

Schreibe ein Programm `PatientLoeschen.java`:

1. Frage den Benutzer nach einer ID
2. Lösche den Patienten mit `em.remove()` in einer Transaktion
3. Gib aus, ob der Patient gelöscht wurde oder nicht existiert

### UE_12.1_8: Transaktionen verstehen

Schreibe ein Programm `TransaktionsTest.java`:

1. Beginne eine Transaktion
2. Speichere einen neuen Patienten
3. Löse bewusst einen Fehler aus (z. B. `int x = 1 / 0`)
4. Fange den Fehler und führe `rollback()` aus
5. Überprüfe, dass der Patient nicht in der Datenbank ist
6. Führe denselben Code ohne Fehler aus – der Patient sollte gespeichert werden
