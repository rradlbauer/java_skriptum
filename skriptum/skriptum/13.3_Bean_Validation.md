# 13.3 Bean Validation – Eingaben prüfen

**Bean Validation** (Teil von Jakarta EE, Umsetzung z. B. Hibernate Validator) erlaubt es, Datenfelder mit **Annotations-Regeln** zu versehen. Spring führt diese Prüfungen automatisch aus, wenn ein Objekt mit `@Valid` markiert wird.

## Validierungs-Annotationen

In den Entitäten der Impf-Applikation findest du diese Annotationen:

```java
@NotBlank(message = "Name is required")
private String name;

@NotNull(message = "Birthdate is required")
private LocalDate birthdate;
```

| Annotation | Prüfung | Beispiel |
|------------|---------|----------|
| `@NotBlank` | Nicht `null` und nicht nur Leerzeichen | Namen, Arzt |
| `@NotNull` | Nicht `null` | Datum |
| `@NotEmpty` | Nicht `null` und nicht leer | Listen |
| `@Size(min, max)` | Längenbegrenzung | Zeichenketten |
| `@Min` / `@Max` | Zahlenbereich | Alter |
| `@Pattern(regexp)` | Passt zum Regex-Muster | SSN |

Die `message`-Eigenschaft definiert die Fehlermeldung, die angezeigt wird, wenn die Prüfung fehlschlägt.

## Validierung im Controller aktivieren

Damit Spring die Regeln prüft, muss das Objekt mit **`@Valid`** markiert werden. Der Parameter **`BindingResult`** muss **direkt danach** stehen, um die Fehler aufzufangen:

```java
@PostMapping("/patients/register")
public String register(@Valid @ModelAttribute Patient patient, BindingResult result) {
    if (result.hasErrors()) {
        return "patient-register";   // Formular mit Fehlermeldungen erneut anzeigen
    }
    patientRepository.save(patient);
    return "redirect:/patients";
}
```

Der Ablauf:

1. Das Formular wird abgeschickt (`@ModelAttribute Patient patient`)
2. `@Valid` löst die Prüfung aller Regeln aus
3. Fehler landen im `BindingResult`
4. `result.hasErrors()` ist `true`, wenn mindestens eine Regel verletzt ist
5. Bei Fehlern wird die View erneut angezeigt – mit den Fehlermeldungen

**Wichtig:** Ohne `BindingResult` direkt nach `@Valid` würde eine Validierungs-Exception ausgelöst und der Nutzer bekäme einen Fehler-Seite.

## Fehler in der View anzeigen

Das Formular-Template (Kapitel 13.4) zeigt die Fehler pro Feld an:

```html
<input type="text" th:field="*{name}"
       th:classappend="${#fields.hasErrors('name')} ? 'is-invalid'"/>
<div class="invalid-feedback" th:errors="*{name}"></div>
```

- `th:field="*{name}"` bindet das Eingabefeld an das Objekt-Attribut
- `#fields.hasErrors('name')` prüft, ob das Feld Fehler hat
- `th:errors="*{name}"` zeigt die Fehlermeldung an

So bekommt der Nutzer sofortiges Feedback, ohne dass ungültige Daten gespeichert werden.

## Zusammenfassung

### Wichtige Begriffe
- Bean Validation
- `@NotBlank` / `@NotNull` / `@Size` / `@Pattern`
- `@Valid`
- `BindingResult` / `result.hasErrors()`
- Fehlermeldungen (`message`)

### Das sollst du können
- Validierungs-Regeln mit Annotationen an Felder hängen
- `@Valid` + `BindingResult` in einem Controller verwenden
- Erklären, warum `BindingResult` direkt nach `@Valid` stehen muss
- Validierungsfehler in der View anzeigen
