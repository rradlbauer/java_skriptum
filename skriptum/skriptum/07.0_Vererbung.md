# 07.0 Vererbung und Polymorphie

Vererbung kennst du bereits aus Python. In Java wird sie mit `extends` umgesetzt und ist strenger typisiert.

## Vererbung in Java

```java
public class Examination {
    protected String patientName;
    protected String date;

    public Examination(String patientName, String date) {
        this.patientName = patientName;
        this.date = date;
    }

    public void perform() {
        System.out.println("Examination for " + patientName + " on " + date);
    }
}
```

```java
public class BloodTest extends Examination {
    private String bloodValue;
    private double measuredValue;

    public BloodTest(String patientName, String date, String bloodValue, double measuredValue) {
        super(patientName, date);  // Call parent constructor
        this.bloodValue = bloodValue;
        this.measuredValue = measuredValue;
    }
}
```

### super vs. super() 

- `super()` ruft den Konstruktor der Elternklasse auf **muss die erste Anweisung im Konstruktor sein**
- `super.methodenname()` ruft eine überschriebene Methode der Elternklasse auf

Vergleich mit Python:

| Python | Java |
|--------|------|
| `super().__init__(name)` | `super(name)` |
| `super().methode()` | `super.methode()` |

## Methoden überschreiben (@Override)

Eine Unterklasse kann Methoden der Oberklasse **überschreiben** (override):

```java
public class BloodTest extends Examination {
    // ...

    @Override
    public void perform() {
        System.out.println("Blood test for " + patientName);
        System.out.println("  Value: " + bloodValue + " = " + measuredValue);
    }
}
```

Die `@Override`-Annotation ist optional, aber empfohlen:
- Der Compiler prüft, ob die Methode tatsächlich eine Methode der Oberklasse überschreibt
- Schützt vor Tippfehlern (z. B. `perform()` vs. `perforrm()`)

Wichtig: In Python werden Methoden immer dynamisch überschrieben. In Java muss die Methodensignatur **exakt** übereinstimmen (Name + Parameter + Rückgabetyp).

## Die Klasse Object – die Wurzel der Vererbung

Jede Klasse in Java erbt **automatisch** von der Klasse `Object` (aus `java.lang`). Das gilt auch, wenn du kein `extends` schreibst – der Compiler ergänzt es stillschweigend:

```java
public class Patient { ... }
// ist identisch mit:
public class Patient extends Object { ... }  // implizit
```

Weil jede Klasse von `Object` erbt, besitzt jedes Objekt gewisse Standardmethoden. Die wichtigste davon ist `toString()`.

### toString() – die Objekt-Darstellung

`Object.toString()` liefert eine **Standard-Darstellung** des Objekts: den Klassennamen, gefolgt von `@` und einer Hexadzimalzahl (interner Speicherort). Das ist für dich meistens nutzlos:

```java
Patient p = new Patient("Anna", 25);
System.out.println(p);
// Ausgabe z. B.: Patient@7f31245a  ← nur ClassName@hashCode
```

Deshalb überschreibst du `toString()`, um eine **lesbare Darstellung** zu definieren:

```java
public class Patient {
    private String name;
    private int age;

    public Patient(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return "Patient: " + name + " (" + age + " years)";
    }
}
```

Jetzt liefert `System.out.println(p)` eine verständliche Ausgabe:

```java
Patient p = new Patient("Anna", 25);
System.out.println(p);   // Patient: Anna (25 years)
String info = "" + p;    // impliziter Aufruf von toString() bei String-Verkettung
```

`toString()` wird an vielen Stellen **automatisch** aufgerufen:
- bei `System.out.println(obj)`
- bei `"..." + obj` (String-Verkettung)
- bei `System.out.printf("%s", obj)`

Mit `@Override` stellst du sicher, dass `toString()` 
tatsächlich die Methode von `Object` überschreibt. 
Gute `toString()`-Darstellungen machen Debugging und 
Ausgaben deutlich einfacher.

Das ist vergleichbar mit Python, wo du `__str__()` überschreibst:

```python
class Patient:
    def __init__(self, name, age):
        self.name = name
        self.age = age
    
    def __str__(self):
        return f"Patient: {self.name} ({self.age} years)"
        
p = Patient("Anna", 25)
print(p)  # Patient: Anna (25 years)
```
        

## Basisklassen-Methode von der überschreibenden Methode aufrufen

Oft möchtest du in einer überschreibenden Methode **zusätzlich** zur Logik der Oberklasse eigene Logik ausführen. Dafür rufst du die Basisklassen-Methode mit `super.methodenname()` auf:

```java
public class BloodTest extends Examination {
    // ...

    @Override
    public void perform() {
        super.perform();   // Calls the base-class method (Examination.perform)
        System.out.println("  Blood value: " + bloodValue + " = " + measuredValue);
    }
}
```

Der Aufruf `super.perform()` führt zuerst die ursprüngliche `perform()`-Methode der Klasse `Examination` aus und anschließend läuft der Code der überschreibenden Methode weiter. So bleibt die gemeinsame Logik der Basisklasse erhalten, ohne sie zu duplizieren.

Wichtig ist der Unterschied zu `super()`:
- `super()` ruft den **Konstruktor** der Elternklasse auf und darf nur als **erste Anweisung im Konstruktor** stehen
- `super.methodenname(...)` ruft eine **beliebige Methode** der Elternklasse auf und kann **überall im Methodenrumpf** stehen

Vergleich mit Python:

```python
class BloodTest(Examination):
    def perform(self):
        super().perform()   # Calls the base-class method
        print("  Blood value:", self.bloodValue, "=", self.measuredValue)
```

Ohne den `super()`-Aufruf müsstest du die Ausgabe "Examination for ..." in jeder Unterklasse neu schreiben – das wäre Code-Duplikation. Mit `super()` erweiterst du die Basislogik zentral.

## Polymorphie

Polymorphie bedeutet, dass eine Referenz vom Typ der Oberklasse auf ein Objekt der Unterklasse zeigen kann:

```java
Examination u1 = new Examination("Anna", "2024-01-15");
Examination u2 = new BloodTest("Ben", "2024-01-15", "Blood Sugar", 95.0);

u1.perform();  // Calls Examination.perform()
u2.perform();  // Calls BloodTest.perform() (even though type is Examination!)
```

Das ist das Kernprinzip der Polymorphie: **Welche Methode aufgerufen wird, entscheidet der Objekttyp zur Laufzeit, nicht der Referenztyp zur Compile-Zeit.**

### Vergleich Python vs. Java

```python
# Python – Duck Typing
def process(examination):
    examination.perform()  # As long as the method exists
```

```java
// Java – Polymorphie mit Vererbung
public void process(Examination u) {
    u.perform();  // u MUST be of type Examination (or subclass)
}
```

Java ist hier strenger: Der Typ muss zur Compile-Zeit bekannt sein. Python akzeptiert jedes Objekt, das die Methode hat (Duck Typing).

## Protected

`protected` erlaubt den Zugriff in:
- Derselben Klasse
- Demselben Package
- Allen Unterklassen (auch in anderen Packages)

Das ist ideal für Attribute, die in Unterklassen verwendet werden sollen.

## Zusammenfassung

### Wichtige Begriffe
- `extends`
- `super()` (Konstruktor-Aufruf)
- `super.methode()` (Basisklassen-Methode aufrufen)
- Vererbung (inheritance)
- Überschreiben (override)
- `@Override`-Annotation
- Klasse `Object` (Wurzelklasse)
- `toString()` überschreiben
- Polymorphie
- `protected`

### Das sollst du können
- Eine Klassenhierarchie mit `extends` aufbauen
- Methoden mit `@Override` überschreiben
- Von der überschreibenden Methode aus die Basisklassen-Methode mit `super.methode()` aufrufen
- Erklären, dass jede Klasse implizit von `Object` erbt
- `toString()` überschreiben, um eine lesbare Objekt-Darstellung zu erhalten
- Den Unterschied zwischen Referenztyp und Objekttyp erklären
- Polymorphie anwenden
