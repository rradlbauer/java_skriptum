# 05.2 Konstruktoren, Getter/Setter und this

## Konstruktoren

Ein **Konstruktor** initialisiert ein neues Objekt. In Python heißt er `__init__`, in Java hat er **denselben Namen wie die Klasse** und **keinen Rückgabetyp** (nicht einmal `void`).

```java
public class Patient {
    private String name;
    private int age;

    // Constructor
    public Patient(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

Erzeugung eines Objekts:

```java
Patient p = new Patient("Anna", 25);
```

### Default-Konstruktor

Wenn du **keinen** Konstruktor definierst, erstellt Java automatisch einen parameterlosen Default-Konstruktor. Sobald du einen eigenen Konstruktor definierst, gibt es keinen Default-Konstruktor mehr.

```java
public class Patient {
    private String name;

    // NO constructor → default constructor available
}

// Usage:
Patient p = new Patient();  // default constructor
```

## this vs. self

`this` in Java entspricht `self` in Python. Es verweist auf das aktuelle Objekt.

```java
public class Patient {
    private String name;

    public Patient(String name) {
        this.name = name;  // this.name = attribute, name = parameter
    }
}
```

Unterschiede:

| Aspekt | Python | Java |
|--------|--------|------|
| Schlüsselwort | `self` | `this` |
| Muss angegeben werden? | Ja, als erster Parameter | Nein, es ist implizit |
| Muss verwendet werden? | Ja, bei Attributzugriff | Nur bei Namenskonflikten nötig |

In Java kannst du `this` weglassen, wenn es keine Verwechslung gibt:

```java
public void display() {
    System.out.println(name);  // this.name is implicit
}
```

`this` funktioniert genauso wie `self` in Python – du kannst damit nicht nur auf Attribute, sondern auch auf Methoden zugreifen:

```java
public class Patient {
    private String name;

    public void setName(String name) {
        this.name = name;
    }

    public void display() {
        this.setName("Anna");   // Method call with this (optional)
        System.out.println(this.name);
    }
}
```

Wie bei Attributen ist `this` auch bei Methoden optional – 
solange es keine Verwechslung gibt. 
Der Aufruf `setName("Anna")` ist identisch zu `this.setName("Anna")`.

## Getter und Setter

Da Attribute `private` sind, braucht es öffentliche Zugriffsmethoden. 
Diese werden **Getter** (für Lesen) und **Setter** (für Schreiben) genannt.

```java
public class Patient {
    private String name;
    private double height;  // in meters

    // Constructor
    public Patient(String name, double height) {
        this.name = name;
        this.height = height;
    }

    // Getter
    public String getName() {
        return name;
    }

    // Getter
    public double getHeight() {
        return height;
    }

    // Setter with validation
    public void setHeight(double height) {
        if (height > 0 && height < 3.0) {
            this.height = height;
        }
        else {
            throw new IllegalArgumentException("Invalid height: " + height);
        }
    }

    // Setter (simple)
    public void setName(String name) {
        this.name = name;
    }
}
```

### Konventionen für Getter/Setter

| Attribute | Getter | Setter |
|-----------|--------|--------|
| `name` | `getName()` | `setName(String name)` |
| `age` | `getAge()` | `setAge(int age)` |
| `bodyHeight` | `getBodyHeight()` | `setBodyHeight(double height)` |
| `boolean active` | `isActive()` | `setActive(boolean active)` |

Das Setzen von Gettern/Settern kann IntelliJ für dich übernehmen: 
Rechtsklick → **Generate → Getter and Setter** (oder `Alt + Einfg`).
Diese Unterstützung solltest du auf jeden Fall verwenden.
Sie spart Zeit und stellt sicher, 
dass die Konventionen eingehalten werden.
