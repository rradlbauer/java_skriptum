# 13.0 Spring Boot – Grundlagen

**Spring Boot** ist ein Framework auf Basis von **Spring**, das die Entwicklung von Java-Anwendungen (vor allem Web-Anwendungen) stark vereinfacht. Es kümmert sich um viele Dinge, die du sonst selbst konfigurieren müsstest: einen eingebauten Webserver, die Verbindung zu Datenbanken, die Verarbeitung von HTTP-Anfragen und vieles mehr – oft ohne dass du eine einzige Zeile Konfigurationscode schreiben musst.

In den Kapiteln 13.x lernst du die Grundlagen, die nötig sind, um die Impfverwaltungs-Applikation aus dem Projekt zu verstehen. Diese Anwendung verwaltet **Patienten** und deren **Impfungen** über eine Weboberfläche.

## Was macht Spring Boot?

Spring Boot verfolgt das Prinzip der **Konvention vor Konfiguration** (kennst du bereits von Maven aus Kapitel 11.0). Es bringt Standard-Konfigurationen mit, sodass du nur die Dinge anpassen musst, die von der Norm abweichen.

Vorteile:
- **Eingebauter Webserver** (z. B. Tomcat) – deine Anwendung läuft direkt, kein separater Server nötig
- **Auto-Konfiguration** – Spring Boot richtet Bausteine ein, sobald deren Bibliothek im Klassenpfad ist
- **Starter-Dependencies** – vorgefertigte Dependency-Pakete in Maven
- Wenig Boilerplate-Code

## Starters in der pom.xml

Im Projekt arbeite ich mit **Spring Boot Starter**-Dependencies. Ein Starter bündelt eine Bibliothek und all ihre Abhängigkeiten. Im Projekt wird u. a. Folgendes verwendet:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-thymeleaf</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

| Starter | Wofür? |
|---------|--------|
| `spring-boot-starter-web` | Web-Anwendung, HTTP-Anfragen verarbeiten (Spring MVC) |
| `spring-boot-starter-thymeleaf` | Server-seitiges Rendering von HTML-Seiten (Kapitel 13.4) |
| `spring-boot-starter-data-jpa` | Datenbankzugriff über JPA + Spring Data (Kapitel 13.2) |
| `spring-boot-starter-validation` | Bean Validation (Kapitel 13.3) |
| `mysql-connector-j` | JDBC-Treiber für MySQL |

Der `pom.xml`-Parent `spring-boot-starter-parent` verwaltet die Versionen aller Starter zentral, sodass du keine Versionsnummern angeben musst. Außerdem ist das Plugin `spring-boot-maven-plugin` eingetragen, das das Starten der Anwendung über Maven ermöglicht.

## Die Hauptklasse (@SpringBootApplication)

Jede Spring-Boot-Anwendung hat eine Hauptklasse mit `main`-Methode:

```java
package com.health.vax;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class VaxApplication {
    public static void main(String[] args) {
        SpringApplication.run(VaxApplication.class, args);
    }
}
```

`@SpringBootApplication` ist eine **Kombination** aus mehreren Annotationen:

| Annotation | Bedeutung |
|------------|-----------|
| `@SpringBootConfiguration` | Markiert die Klasse als Konfiguration (kann Beans definieren) |
| `@EnableAutoConfiguration` | Aktiviert die automatische Konfiguration von Spring Boot |
| `@ComponentScan` | Durchsucht das Package und alle Unter-Packages nach Komponenten |

Wichtig: `@ComponentScan` startet beim Package der Hauptklasse (`com.health.vax`). Alle mit `@Controller`, `@Service`, `@Repository` u. ä. markierten Klassen in `com.health.vax.*` werden automatisch gefunden und als **Beans** verwaltet.

## Starten der Anwendung

Die Anwendung startest du entweder direkt in IntelliJ (Run auf der `main`-Methode) oder per Maven:

```bash
mvn spring-boot:run
```

Beim Start:
1. Spring Boot führt die Auto-Konfiguration aus
2. Der eingebaute Tomcat-Server startet auf Port `8080`
3. Datenbankverbindungen werden aufgebaut (siehe unten)
4. In der Konsole erscheint z. B. `Started VaxApplication`

Die Web-Oberfläche ist danach unter `http://localhost:8080/` erreichbar.

## Konfiguration über application.properties

Spring-Boot-Einstellungen legst du in der Datei `src/main/resources/application.properties` ab:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/vax
spring.datasource.username=root
spring.datasource.password=geheim

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

| Property | Bedeutung |
|----------|-----------|
| `spring.datasource.url` | JDBC-URL zur Datenbank |
| `spring.datasource.username` / `.password` | Zugangsdaten |
| `spring.jpa.hibernate.ddl-auto` | Schema-Verhalten (wie `hibernate.hbm2ddl.auto` aus Kapitel 12.1) |
| `spring.jpa.show-sql` | Zeigt generierte SQL-Ausdrücke an |

Spring Boot liest diese Datei automatisch und konfiguriert die Bausteine entsprechend – du musst keinen Code dafür schreiben.

## Zusammenfassung

### Wichtige Begriffe
- Spring Boot, Spring
- Starter-Dependency
- Auto-Konfiguration, Konvention vor Konfiguration
- `@SpringBootApplication` (`@SpringBootConfiguration`, `@EnableAutoConfiguration`, `@ComponentScan`)
- `application.properties`
- `mvn spring-boot:run`, eingebauter Tomcat, Port 8080

### Das sollst du können
- Erklären, was Spring Boot ist und welche Vorteile es bietet
- Wichtige Starter-Dependencies in der `pom.xml` benennen
- Die Rolle von `@SpringBootApplication` erklären
- Die Anwendung starten und die Konfiguration in `application.properties` verstehen
