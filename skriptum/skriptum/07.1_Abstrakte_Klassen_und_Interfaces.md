# 07.1 Abstrakte Klassen und Interfaces

Abstrakte Klassen und Interfaces sind zentrale Werkzeuge, um **Schnittstellen von Implementierungen zu trennen**. In Python gibt es dafür das `abc`-Modul.

## Abstrakte Klassen

Eine **abstrakte Klasse** kann nicht direkt instanziiert werden. Sie dient als Vorlage für Unterklassen:

```java
public abstract class Examination {
    protected String patientName;
    protected String date;

    public Examination(String patientName, String date) {
        this.patientName = patientName;
        this.date = date;
    }

    // Abstract method: no implementation, must be overridden by subclasses
    public abstract void perform();

    // Concrete method: is inherited
    public String getPatientName() {
        return patientName;
    }
}
```

```java
public class BloodTest extends Examination {
    private String bloodValue;
    private double measuredValue;

    public BloodTest(String patientName, String date, String bloodValue, double measuredValue) {
        super(patientName, date);
        this.bloodValue = bloodValue;
        this.measuredValue = measuredValue;
    }

    @Override
    public void perform() {   // Must be implemented!
        System.out.println(bloodValue + ": " + measuredValue);
    }
}
```

```java
// Examination u = new Examination(...);  // Compiler error! abstract class
Examination u = new BloodTest("Anna", "2024-01-15", "HbA1c", 5.7);
u.perform();
```

## Interfaces

Ein **Interface** definiert einen Vertrag (eine Schnittstelle), den eine Klasse erfüllen muss. Es enthält nur Methodensignaturen (keine Implementierung, keine Attribute).

```java
public interface Treatable {
    void treat();               // automatically public abstract
    String getDiagnosis();      // automatically public abstract
}
```

```java
public class Patient implements Treatable {
    private String name;
    private String diagnosis;

    public Patient(String name, String diagnosis) {
        this.name = name;
        this.diagnosis = diagnosis;
    }

    @Override
    public void treat() {
        System.out.println(name + " is being treated for: " + diagnosis);
    }

    @Override
    public String getDiagnosis() {
        return diagnosis;
    }
}
```

### Mehrere Interfaces implementieren

Anders als bei Vererbung (nur eine Oberklasse) kann eine Klasse **mehrere Interfaces implementieren**:

```java
public interface Vaccinable {
    void vaccinate(String vaccine);
}

public interface Examinable {
    void examine(String type);
}

public class Patient implements Treatable, Vaccinable, Examinable {
    // Must implement ALL methods from all interfaces
    @Override public void treat() { /* ... */ }
    @Override public String getDiagnosis() { return ""; }
    @Override public void vaccinate(String vaccine) { /* ... */ }
    @Override public void examine(String type) { /* ... */ }
}
```

### Default-Methoden in Interfaces (Java 8+)

Seit Java 8 können Interfaces auch **default-Methoden** mit einer Standard-Implementierung enthalten:

```java
public interface Treatable {
    void treat();

    default void document() {
        System.out.println("Treatment documented.");
    }
}
```

## Abstrakte Klasse vs. Interface

| Kriterium | Abstrakte Klasse | Interface |
|-----------|:---:|:---:|
| Kann Attribute haben | ✓ | ✗ |
| Kann Konstruktoren haben | ✓ | ✗ |
| Kann normale Methoden haben | ✓ | nur default-Methoden |
| Kann abstrakte Methoden haben | ✓ | ✓ |
| Mehrfachvererbung möglich | ✗ (nur eine O.K.) | ✓ (mehrere Interfaces) |
| Verwendung | `extends` | `implements` |

**Faustregel:**
- Verwende eine **abstrakte Klasse**, wenn die Klassen eine gemeinsame Basis mit Code teilen
- Verwende ein **Interface**, wenn du einen Vertrag definieren willst, den viele unterschiedliche Klassen erfüllen können

## Trennung von Schnittstelle und Implementierung

Interfaces ermöglichen die saubere Trennung von "was" und "wie":

```java
// Schnittstelle (was)
public interface DiagnosticTool {
    String analyze(String data);
}

// Implementierung 1 (wie)
public class BloodAnalysis implements DiagnosticTool {
    @Override
    public String analyze(String data) {
        return "Blood analysis: " + data;
    }
}

// Implementierung 2 (wie)
public class MRT implements DiagnosticTool {
    @Override
    public String analyze(String data) {
        return "MRT finding: " + data;
    }
}

// Verwendung (Programmieren gegen die Schnittstelle)
public class Doctor {
    public void diagnose(DiagnosticTool tool, String data) {
        String result = tool.analyze(data);
        System.out.println(result);
    }
}
```

## Vergleich mit Python

```python
# Python – abc module
from abc import ABC, abstractmethod

class Examination(ABC):
    @abstractmethod
    def perform(self):
        pass

# Python has no real Interface concept (ABC is used for that)
```

In Java wird die Trennung von Schnittstelle und Implementierung durch die Sprachsyntax erzwungen.

## Zusammenfassung

### Wichtige Begriffe
- `abstract class` / `abstract method`
- `interface` / `implements`
- `default`-Methode
- Programmieren gegen die Schnittstelle
- Vertrag (contract)

### Das sollst du können
- Abstrakte Klassen definieren und verwenden
- Interfaces definieren und implementieren
- Mehrere Interfaces kombinieren
- Den Unterschied zwischen abstrakter Klasse und Interface erklären
- Gegen Schnittstellen statt gegen Implementierungen programmieren
