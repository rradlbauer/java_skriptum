# 13.2 Spring Data JPA – Repositories

In Kapitel 12.1 und 12.2 hast du mit dem `EntityManager` (JPA) direkt gearbeitet – du hast `persist()`, `find()`, `merge()` und `remove()` manuell aufgerufen. **Spring Data JPA** vereinfacht das: Du definierst nur ein **Interface**, und Spring erzeugt automatisch die Implementierung mit allen notwendigen Datenbankoperationen.

## Das Repository-Muster

Ein **Repository** kapselt den Datenbankzugriff für eine Entität. Spring Data JPA stellt dafür das Interface `JpaRepository` bereit, das viele fertige Methoden mitbringt:

```java
package com.health.vax.repository;

import com.health.vax.entity.Patient;
import org.springframework.data.jpa.repository.JpaRepository;

public interface PatientRepository extends JpaRepository<Patient, Long> {
}
```

- `<Patient, Long>`: Erster Typ ist die Entität, zweiter Typ ist der Typ der `@Id`
- Das Interface ist leer – alle Standard-Methoden kommen von `JpaRepository`

Spring erzeugt zur Laufzeit automatisch eine Implementierung. Du musst **keine Klasse schreiben** – du kannst das Interface einfach in einen Controller injizieren.

## Fertige Methoden von JpaRepository

| Methode | SQL-Äquivalent |
|---------|----------------|
| `findAll()` | `SELECT * FROM ...` |
| `findById(id)` | `SELECT ... WHERE id = ?` |
| `save(entity)` | `INSERT` (neu) oder `UPDATE` (vorhanden) |
| `deleteById(id)` | `DELETE WHERE id = ?` |
| `count()` | `SELECT COUNT(*)` |
| `existsById(id)` | Prüft, ob ein Datensatz existiert |

Beispiel:

```java
List<Patient> all = patientRepository.findAll();
Patient p = patientRepository.findById(7L).orElseThrow();
patientRepository.save(p);
```

`findById` liefert ein `Optional<Patient>`. Mit `.orElseThrow()` erhältst du das Objekt direkt oder eine Exception, falls es nicht existiert.

## Ableitete Query-Methoden

Zusätzlich zu den Standard-Methoden kannst du **eigene Abfragen** nur durch den Methodennamen definieren. Spring leitet das SQL aus dem Namen ab:

```java
public interface VaccinationRepository extends JpaRepository<Vaccination, Long> {
    List<Vaccination> findByPatientId(Long patientId);
}
```

`findByPatientId` erzeugt automatisch `SELECT * FROM vaccinations WHERE patient_id = ?`. Die Regeln:

- `findBy` + **Attributname**: `findByPatientId` sucht nach dem Attribut `patientId`
- Bei verschachtelten Beziehungen sucht die Punkt-Notation: `findByPatientName`
- Rückgabetyp kann `List<T>`, `Optional<T>` oder `T` sein

### Logische Verknüpfungen

| Methodenname | Bedeutung |
|--------------|-----------|
| `findByNameAndAge` | `WHERE name = ? AND age = ?` |
| `findByNameOrAge` | `WHERE name = ? OR age = ?` |
| `findByAgeLessThan` | `WHERE age < ?` |
| `findByNameStartingWith` | `WHERE name LIKE '?%'` |
| `findByNameContaining` | `WHERE name LIKE '%?%'` |

## Injection in den Controller

Repositories werden über den **Konstruktor** in den Controller injiziert – das übernimmt Spring automatisch (Konstruktor-Injection):

```java
@Controller
public class VaccinationController {

    private final VaccinationRepository vaccinationRepository;
    private final PatientRepository patientRepository;

    public VaccinationController(VaccinationRepository vaccinationRepository,
                                 PatientRepository patientRepository) {
        this.vaccinationRepository = vaccinationRepository;
        this.patientRepository = patientRepository;
    }
}
```

`private final` + Konstruktor ist die empfohlene Art, Abhängigkeiten zu injizieren: Die Abhängigkeiten sind klar, unveränderlich und leicht zu testen.

## Transaktionen

Spring Data JPA verwaltet **Transaktionen** automatisch. Jede Repository-Methode wird innerhalb einer Transaktion ausgeführt. Für zusammengesetzte Operationen kannst du eine Service-Methode mit `@Transactional` markieren – dann läuft die gesamte Methode in einer einzigen Transaktion.

## Zusammenfassung

### Wichtige Begriffe
- Repository-Muster
- `JpaRepository<Entity, Id>`
- Konstruktor-Injection
- Abgeleitete Query-Methoden (`findBy...`)
- `Optional` (`orElseThrow`)
- `@Transactional`, automatische Transaktionen

### Das sollst du können
- Ein Repository-Interface durch `extends JpaRepository` erstellen
- Die Standard-Methoden (`findAll`, `findById`, `save`, `delete`) verwenden
- Eigene Query-Methoden über den Methodennamen definieren
- Repositories per Konstruktor-Injection in den Controller einbinden
