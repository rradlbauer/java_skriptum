# 03.0 Grundlegende Syntax und strenge Typisierung

Nach den ersten Experimenten mit JShell und dem ersten Java-Programm 
sehen wir uns die Java-Syntax nun systematisch an.

## Grundlegende Syntaxregeln

| Aspekt | Java | Python |
|--------|------|--------|
| **Statement-Ende** | `;` (Semikolon) | Zeilenumbruch |
| **Code-Blöcke** | `{ ... }` | Einrückung |
| **Variablen-Deklaration** | `Typ name = wert;` | `name = wert` |
| **Kommentare** | `//` und `/* */` | `#` |
| **Case-Sensitivity** | Groß-/Kleinschreibung wichtig | Groß-/Kleinschreibung wichtig |

## Beispiel: Blockstruktur

```java
if (temperature > 37.5) {
    System.out.println("Fever!");
    System.out.println("Please see a doctor.");
} else {
    System.out.println("Temperature normal.");
}
```

```python
# Python equivalent
if temperature > 37.5:
    print("Fever!")
    print("Please see a doctor.")
else:
    print("Temperature normal.")
```

## Strenge Typisierung

Java ist **stark und statisch typisiert**. Jede Variable hat einen festen Typ, der bereits zur Compile-Zeit bekannt sein muss.

```java
int count = 10;        // OK
count = "ten";         // Compiler error! String cannot be assigned to int
```

In Python würde das gleiche Beispiel funktionieren, 
da Python **dynamisch typisiert** ist:

```python
count = 10             # OK
count = "ten"          // also OK (dynamic typing)
```

Die strenge Typisierung hat Vor- und Nachteile:

\+ Viele Fehler werden bereits beim Kompilieren erkannt  
\+ Der Code ist selbst-dokumentierend (Typen sind sichtbar)  
\+ Bessere Unterstützung durch die IDE (Autovervollständigung, Refactoring)  
\- Mehr Aufwand bei der Entwicklung (Typen müssen immer angegeben werden)  
\- Weniger flexibel

## Deklaration und Initialisierung

```java
int age;                  // Declaration (no value yet)
age = 25;                 // Initialization (assign value)

double height = 1.75;     // Declaration + initialization

final double VAT = 0.20;  // Constant (with final, cannot be changed)
```

Das Schlüsselwort `final` macht eine Variable zu einer Konstanten – 
es kann kein anderer Wert zugewiesen werden.

## Namenskonventionen

In allen gängigen Programmiersprachen gibt es Namenskonventionen.
Das sind Regeln, an welche man sich halten sollte,
damit der Code auch für andere Entwickler gut lesbar ist.
Das Programm ist auch compilierbar und lauffähig, 
wenn man sich nicht daran hält,
aber das ist unprofessionell.

Hier die Namenskonventionen für Java:

| Element | Convention | Example                          |
|---------|-----------|----------------------------------|
| Variables | camelCase, starts with lowercase | `patientName`, `bodyHeight`      |
| Methods | camelCase, starts with lowercase | `calculateBMI()`, `getPatient()` |
| Classes | PascalCase, starts with uppercase | `PatientName`, `HospitalManager` |
| Constants | UPPER_SNAKE_CASE | `MAX_PATIENTS`, `PI`             |
| Packages | lowercase, dot-separated | `com.example.medical`            |
